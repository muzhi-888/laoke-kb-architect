# 01 · 知识管理体系：什么时候该建知识库

> 本文件讲"为什么"和"何时"建知识库，以及主流方法论的取舍。解决"我到底需不需要建库"的迷茫。

## 一、先判断：你这摊信息，值不值得建库

不是所有信息都该进知识库。建库的「触发条件」满足任意两条就该动手：

1. **反复被问**：同一类问题每周被问 3 次以上（产品 FAQ、入职指引、故障处理）。
2. **多人协作**：≥2 人需要查看同一份权威信息，且版本经常对不上。
3. **知识随人走**：核心信息只存在某个人脑子里，他一休假就断档。
4. **体量大、检索难**：文档超过 50 篇，靠文件夹+文件名已经找不到东西。
5. **要喂给 AI**：想把资料接进 ima 知识库 / 向量检索 / Agent 上下文，必须有结构化条目。

反过来，**不该建库**的情况：一次性临时文档、纯流水记录（用日志系统）、保密性极高且不出团队的信息（用加密笔记）。

## 二、四种主流方法论，按场景选

### 1. Zettelkasten（卡片盒）—— 适合「想法沉淀」
- 核心：每条笔记只讲一个原子概念，靠「链接」而非文件夹组织。
- 优点：知识网状生长，容易涌现新联系，适合研究/写作/思考。
- 缺点：上手成本高，对「找答案」型业务支持弱。
- 本 Skill 适配：把长文切成原子条目后，用 `tags` + `summary` 当链接锚点。

### 2. PARA（项目/领域/资源/归档）—— 适合「行动导向」
- 项目（有截止）：今年要上的新功能。
- 领域（长期责任）：客服体系、内容运营。
- 资源（将来可能有用）：行业报告、竞品截图。
- 归档（ inactive）：做完的项目。
- 优点：和「干活」对齐，不囤垃圾。
- 本 Skill 适配：`category` 字段直接映射 PARA 的四大类。

### 3. 第二大脑（Building a Second Brain / CODE 法）—— 适合「个人提效」
- Capture 收集 → Organize 组织 → Distill 提炼 → Express 表达。
- 关键动作「Distill」：对每条做 Progressive Summarization（逐层加粗要点）。
- 本 Skill 适配：`summary` 字段就是 Distill 的产物。

### 4. 企业知识库 / 文档中心 —— 适合「团队共享」
- 强分类树 + 权限 + 检索 + 版本。
- 关注点：谁有权看、谁负责更新、过期怎么标。
- 本 Skill 适配：输出 `manifest.json` 可做增量更新依据。

## 三、建库前的三问（动手前必答）

1. **给谁用？** 自己用 → 重检索快；团队用 → 重分类清晰、责任到人；喂 AI → 重结构化、语义完整。
2. **怎么检索？** 关键词检索（tags 要规范）还是语义检索（embedding 友好，正文要完整）？两者都要，本 Skill 同时产出 tags 与完整 body。
3. **谁来维护？** 没有维护人的知识库 3 个月就腐坏。每条最好能追溯到负责人（source 字段）。

## 四、常见误区

- ❌ 贪大求全：一上来想建「公司全部知识」。先从一个高频痛点切（如客服 FAQ）。
- ❌ 只收藏不消化：囤了 500 篇从没读过。建库不是网盘。
- ❌ 过度分类：分了 8 层目录，找东西比百度还累。一般 2-3 层足够。
- ❌ 忽略元数据：只有正文没标签，半年后自己都搜不到。
- ✅ 先有 20 条高质量条目，跑通闭环，再扩。
