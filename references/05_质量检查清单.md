# 05 · 质量检查清单：入库前过一遍

> 建库最怕「建了一堆垃圾」。本文件是可勾选的验收清单 + 常见病害对照表。

## 一、单条验收（每条都过）

- [ ] 标题能当检索词（含对象+动作，≤20 字）
- [ ] 能独立回答一个问题（不依赖其他条也能看懂）
- [ ] 字数在 300-3000 之间（理想 800-1800）
- [ ] 有 category（唯一分类）
- [ ] 有 2-6 个规范标签（来自受控词表）
- [ ] summary 含关键动作/数值，40-80 字
- [ ] 无错别字、无截断、无「待补充」
- [ ] 代码/表格完整未被切断
- [ ] 有「相关」互指（重要条目）

## 二、整库验收（建完过）

- [ ] 分类树 ≤ 3 层，MECE 不重不漏
- [ ] 标签总数 ≤ 30 个规范词
- [ ] 无「其他/杂项」垃圾桶标签
- [ ] slug 全部唯一、语义化、无序号
- [ ] 最长条目 ≤ 3000 字
- [ ] 任意两个问题都能被不同条目命中（无重复覆盖）
- [ ] manifest.json 生成，fingerprint 可用于增量更新
- [ ] 抽样 5 条做检索测试，命中率 100%

## 三、常见病害对照表

| 病害 | 症状 | 治法 |
|---|---|---|
| 碎片化 | 一条只有一句话，答不全 | 合并相邻碎片，或补上下文 |
| 巨无霸 | 一条 5000 字，检索被平均 | 按 H3/段落再切 |
| 标题党 | 标题「新的东西」搜不到 | 改成疑问/动宾式 |
| 标签泛滥 | 一条 15 个标签 | 收敛到受控词表 2-6 个 |
| 孤儿条 | 没有分类，没相关互指 | 归入分类 + 加「相关」 |
| 过期条 | 写的是 2024 规则 | 标生效时间 / 开新 slug 归档 |
| 复制条 | 同一内容两处 | 用 fingerprint 去重，留一删一 |
| 黑话条 | 满篇内部缩写外人看不懂 | 首次出现加解释 |

## 四、增量更新流程（长期维护）

知识库不是建完就完。每次新素材进来：

1. 跑 `kb_chunk.py` 切出新条目到**临时目录**。
2. 比对 `fingerprint`：与旧 `manifest.json` 相同的跳过（已存在）。
3. 新增的 fingerprint → 人工过一遍单条验收清单。
4. 合并进主库，更新 `manifest.json`。
5. 删掉的旧条目 → 标「已归档」，勿直接物理删除（保留追溯）。

## 五、给 AI / 向量库喂数据的注意

- 喂 embedding 前：用 `body`（完整正文）而非 `summary`，embedding 要语义完整。
- 检索返回后：展示用 `title + summary`，点开才看 `body`。
- 权限敏感：含 PII（手机号/身份证）的条目**不要**进公开库，脱敏或留内部。
- 多语言：分库处理，别混切。

## 六、30 秒自检口令

> 拿一条出来，遮住答案问自己：「如果我是用户，搜『怎么退款』能不能找到这条、且这条自己说得清？」——说不清，就还没建好。
