## 一、标准条目结构

```markdown

slug: how-to-refund         # 稳定唯一 ID（URL/检索键）

tags: 退款, 流程, 财务        # 多值标签，受控词表
summary: 在「我的订单」提交退款申请，1-3 个工作日原路退回
source: 产品帮助中心.md       # 来源，便于追溯与维护
fingerprint: a1b2c3d4e5f6    # 去重指纹（内容哈希前 12 位）
---

# 如何申请退款

## 适用场景
已付款但未发货 / 收到货 7 天内无理由。

## 操作步骤
1. 进入「我的订单」找到对应订单。
2. 点击「申请退款」，选择原因（缺货 / 质量问题 / 不想要了）。
3. 上传凭证（可选），提交。
4. 商家 48h 内审核，通过后 1-3 个工作日原路退回。

## 注意事项
- 已拆封定制商品不支持无理由退款。
- 退款进度可在「退款/售后」页查看。

## 相关
- 参见《退款到账时间说明》
- 参见《发票重开流程》
```

## 二、字段字典

| 字段 | 必填 | 说明 | 取值规范 |
|---|---|---|---|
| slug | ✅ | 唯一 ID，检索/URL 键 | 小写字母+数字+连字符，稳定不变 |
| title | ✅ | 人读标题 | 动宾/疑问式，≤ 20 字 |
| category | ✅ | 唯一分类 | 来自受控分类树的一级/二级 |
| tags | ✅ | 多值标签 | 受控词表，2-6 个 |
| summary | ✅ | 一句话摘要 | 40-80 字，含关键动作/数值 |
| source | ✅ | 来源文件/出处 | 便于追溯负责人 |
| fingerprint | ⚠️ | 内容指纹 | 内容哈希前 12 位，增量去重用 |

> 本 Skill 的 `kb_chunk.py` 自动产出全部上述字段，你只需在 `--tags` 注入受控词表。

## 三、正文模板（四种常用型）

### 型 A：操作指南（How-to）
适用：教程、SOP、流程。
```
## 适用场景
## 前置条件
## 操作步骤（编号）
## 常见问题
## 相关
```

### 型 B：概念说明（Reference）
适用：术语、规范、标准。
```
## 定义
## 为什么重要
## 关键规则 / 参数
## 反例
## 相关
```

### 型 C：故障排查（Troubleshooting）
适用：报错、异常、客诉。
```
## 现象
## 可能原因
## 排查步骤
## 解决方案
## 预防
```

### 型 D：案例复盘（Case）
适用：项目、事故、成功经验。
```
## 背景
## 问题/目标
## 做法
## 结果（含数据）
## 可复用经验
```

## 四、summary 的写法

summary 是检索列表的「门面」，写错等于白建。
- ✅ 含「动作 + 关键数值/条件」：「会员年付 8 折，39 元/月起」
- ❌ 空话：「本文介绍会员计费相关内容」
- 长度 40-80 字，能被完整展示在卡片里。

## 五、slug 的命名纪律

- 一旦定下**不要改**（改了历史链接/检索全断）。
- 用「语义 slug」而非「序号」：`how-to-refund` 优于 `doc-037`。
- 冲突时加后缀：`refund-user` / `refund-merchant`，不要用 `refund-2`。
- 本 Skill 自动去重：相同标题第二次出现会追加 `-2`、`-3`，你可在生成后手动改名为语义 slug。

## 六、版本与过期

知识会过时，条目要有「保鲜」机制：
- 规范类条目在 summary 标注生效时间：`（2026-09 生效）`。
- 重大变更开新 slug + 旧条目标「已归档，见《xxx》」，别直接覆盖。
- 用 `manifest.json` 的 `generated_at` 判断整库新鲜度。
