# 03 · 分块策略与粒度：一条知识该切多大

> 切太大检索不准，切太小丢上下文。本文件讲「切多少、在哪切、怎么切」的硬标准。

## 一、先定目标：给谁切？

| 用途 | 推荐粒度 | 理由 |
|---|---|---|
| 人类阅读（ima 知识库条目） | 1 个主题 = 1 条，800-2000 字 | 人一眼看完，不滚动 |
| 向量检索（embedding） | 300-1200 tokens（约 400-1800 字） | 超过会稀释语义，检索召回降 |
| 喂给 Agent 上下文 | 1 个原子知识点，能独立回答一个问题 | 上下文窗口宝贵，宁小勿大 |
| 长文归档 | 按章节，单章不超过 3000 字 | 保留结构，便于跳转 |

本 Skill 默认 `--max-chars 1800`（中文字符），正好覆盖「人读 + 向量」双目标。

## 二、切分锚点优先级（在哪切）

按这个顺序找切口，**高优先级优先**：

1. **语义标题（H2/H3）** —— 最强信号：一个标题下讲一件事。
2. **空行分段** —— 次强：一段一个意思。
3. **句号/换行** —— 兜底：实在没结构才用。

❌ 不要做的事：在句子中间硬切、按固定字数盲切（会切断「因为…所以」）。
✅ 本 Skill 做法：先按 H2 切；某一块超 `max-chars` 再用 H3 切；还没有 H3 且仍超长，才按段落智能拼接。

## 三、重叠（Overlap）要不要？

- **人读条目**：不需要重叠，保持干净。
- **向量检索**：建议 10%-15% 重叠（上一条末尾 + 下一条开头各留一点），避免边界信息丢失。
- 本 Skill 默认不重叠（保持条目纯净）。若你要做向量检索，可在切片后手动让相邻条目共享一个小节，或调小 `max-chars` 让切得更碎、自然覆盖。

## 四、chunk 大小的实测经验

以中文为例（1 汉字 ≈ 1 token 量级）：
- < 300 字：太碎，检索噪声大，一条答不全。
- 300-1800 字：黄金区间，单条能讲清一个小主题。
- 1800-3000 字：勉强，适合结构强的大章节。
- > 3000 字：必须再切，否则检索时「 relevant 段落被平均掉」。

## 五、保留上下文的三种技巧

长文切片最容易丢的是「这条属于哪个大主题」。补救：
1. **继承标题链**：条目里保留 `category` + `hierarchy`（如 `会员与计费 / 怎么开发票`），让人知道来路。
2. **摘要前置**：`summary` 字段用首段实质文字，检索列表一眼看到重点。
3. **首尾互指**：同类条目在正文末加「相关：参见《如何注册账号》」，形成知识网。

## 六、特殊内容的切法

- **表格密集文档**：表格整张归入相邻条目，别从中间切开（表格断裂无法读）。本 Skill 按段落切，表格通常在一个段落内，安全。
- **代码/配置块**：代码块当作一个不可分割单元，归入其说明所在的条目。
- **问答 FAQ**：每个 Q 配其 A 作为一个条目（H3 切分天然适配）。
- **多语言文档**：按语言分两个库，别混切（embedding 跨语言会乱）。

## 七、切片质量的四条验收线

切完后快速过一遍：
1. 任意一条能不能**独立**回答一个问题？（不能 → 切太碎或丢上下文）
2. 任意两条有没有**大量重复**？（有 → 重叠过多，合并）
3. 检索「开发票」能不能命中「怎么开发票」这条？（不能 → 标签/标题没覆盖用户原话）
4. 最长的一条有没有超 3000 字？（有 → 还没切干净）
